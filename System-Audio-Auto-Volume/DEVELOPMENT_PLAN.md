## 1. 交付目标

第一版交付一个本机运行的系统音量监控与自动调节工具：

- 实时显示当前输出设备、系统实际音量、响度、峰值和最近 60 秒趋势；
- 可以设置触发响度、目标区间、音量上下限、压低/恢复速度和手动让路；
- 支持只监控、影子决策、只自动压低三个安全等级；
- 支持 macOS 和 Windows，设备不可控时自动降级；
- 不保存原始音频，不依赖歌曲身份，不训练模型；
- M8 不承诺真正的压缩器或 brick-wall limiter；最终产品必须通过独立 DSP 阶段实现第一个爆音的提前拦截。

## 2. 已锁定的开发原则

1. **先读后写**：先完成真实监控，再允许程序写系统音量。
2. **先影子后闭环**：控制器先只记录“本来会怎么调”，通过回放和实际试听后才执行。
3. **先只降后回升**：第一版自动控制默认只能降低；自动回升是独立门禁。
4. **控制环与界面分离**：界面刷新卡顿不能影响音频采集和控制决策。
5. **实时回调只做轻量工作**：不在音频回调中写文件、调用 UI、阻塞或运行模型。
6. **没有可靠反馈就不闭环**：设备不提供可写音量、无法取得可靠 dB 映射，或捕获位置无法分类时，只监控或运行影子建议。
7. **不提前做桌面壳**：MVP 使用本机后台服务和本地网页；稳定后再决定托盘应用。
8. **DSP 单独立项但属于最终目标**：捕获后压缩/限幅需要音频路由，不能与主音量 MVP 混为一个完成条件，也不能从产品路线中删除。

## 3. MVP 技术形态

### 3.1 进程结构

```text
平台音频适配器
  ├─ macOS：Core Audio tap + 输出设备监听
  └─ Windows：WASAPI loopback + EndpointVolume 监听
          ↓
实时电平计算
  ├─ RMS / Peak（先实现）
  └─ Momentary / Short-term loudness（验证后启用）
          ↓
共享控制器
  ├─ 状态机
  ├─ 静音门和目标区间
  ├─ 用户接管与设备切换
  └─ 只监控 / 影子 / 只降低 / 完整自动
          ↓
平台音量适配器
          ↓
本机状态 API → 监控网页
```

### 3.2 最小技术选择

| 部分 | MVP 选择 | 原因 |
|---|---|---|
| 后台与共享控制器 | Python | 与现有 Windows 录音工具和测试体系一致，便于快速验证 |
| 数值计算 | NumPy，仅在确实需要时使用 | 本地已有；适合处理 PCM 数组，不增加新模型依赖 |
| macOS 采集/设备 | Swift Core Audio helper | 复用现有系统输出 tap 经验，使用原生权限和设备 API |
| Windows 采集 | PyAudioWPatch / WASAPI loopback | 现有代码和测试已经验证基础路径 |
| Windows 音量控制 | EndpointVolume 最小适配器 | 能读写端点主音量并接收变更通知 |
| 监控界面 | 单页 HTML/CSS/JS | 与现有 dashboard 方式一致，跨平台且易于调试 |
| 界面通信 | 本机 HTTP 状态接口，先轮询 | 4 Hz 左右足够显示；控制环独立运行，不需要先上 WebSocket |
| 配置 | 单个版本化 JSON | 可审计、可迁移，不引入数据库 |
| 日志 | JSONL 事件摘要 | 可回放控制决策，不保存音频内容 |

不在 MVP 中引入 Electron、Tauri、数据库、消息队列或机器学习框架。

## 4. 核心数据契约

先固定最小契约，避免 macOS、Windows 和界面各自解释状态。

### 4.1 状态快照 `system-audio.state/v1`

至少包含：

- 时间戳、平台、匿名设备 ID、设备显示名；
- 捕获状态、控制能力、权限和错误；
- RMS dBFS、Peak dBFS；
- 经验证后加入 Momentary/Short-term LUFS；
- 当前系统音量、用户基准音量、自动修正量；
- 控制模式、状态机状态、最后动作和原因；
- 当前生效设置版本。

缺失的测量值必须为 `null` 并带原因，不能伪造成 `0`。

### 4.2 设置 `system-audio.settings/v1`

至少包含：

- `mode`：`monitor` / `shadow` / `lower-only` / `automatic`；
- 触发响度、目标区间；
- 最低/最高系统音量；
- 压低速度、恢复速度；
- 手动让路时长；
- 设备级覆盖设置；
- schema 版本和更新时间。

所有写入在服务端校验：上下限不能反转，目标区间不能反转，速度与等待时间必须在安全范围内。

### 4.3 动作事件 `system-audio.action/v1`

每次决策记录：

- 监测证据；
- 原音量、建议音量、实际写入音量；
- 动作来源：自动、用户、设备变化或恢复；
- 不执行时的阻止原因；
- 控制器版本和设置版本。

## 5. 开发阶段与门禁

### M0：冻结契约与测试场景

任务：

- 确认上述三份 JSON 契约；
- 建立不含版权音频的合成测试信号：静音、稳定音量、阶跃变响、阶跃变轻、短峰值、渐弱；
- 固定状态机名称和设置校验规则；
- 明确第一版只自动压低。

产物：契约 fixture、控制场景表、参数说明。

通过门禁：同一份 fixture 能被服务、控制器测试和界面读取；所有缺失值处理明确。

### M1：共享控制器离线回放

任务：

- 实现纯函数状态机，不接真实设备；
- 输入按时间排列的电平与用户/设备事件，输出动作建议；
- 实现静音门、滞回、最小持续时间、音量边界、用户让路；
- 建立最小自动测试。

必须通过的场景：

- 安静段、暂停和渐弱不建议升音量；
- 短峰值不导致连续大幅调整；
- 持续偏响产生有限步长的下降建议；
- 用户手动操作后停止自动建议；
- 设备切换后进入重新校准；
- 设置异常被拒绝。

产物：共享控制器、离线回放 CLI、测试。

通过门禁：控制器不依赖操作系统、音频设备或网页即可完整测试。

### M2：模拟数据监控界面

任务：

- 建立本机服务和单页监控界面；
- 接入模拟适配器，输出可重复的 60 秒状态序列；
- 实现当前响度、系统音量、用户基准、自动修正和动作原因；
- 实现设置读取、校验、保存和恢复；
- 界面刷新与控制循环分离。

接口先保持最小：

- `GET /api/status`
- `GET /api/history`
- `GET /api/settings`
- `POST /api/settings`
- `POST /api/mode`

产物：可交互监控页、本机 API、模拟适配器。

通过门禁：不接任何真实系统音频，也能演示全部状态与设置；刷新页面不会丢失已保存设置。

### M3：macOS 真实监控，只读

任务：

- 从现有 Core Audio tap 提取最小采集能力，不写录音文件；
- 识别默认输出设备、设备切换和权限变化；
- 输出 RMS、峰值、回调延迟和丢帧；
- 只读取系统音量，不修改；
- 验证扬声器、有线/USB、蓝牙和数字输出的能力差异。

产物：macOS 只读适配器、设备能力报告、真实监控界面。

通过门禁：连续运行 60 分钟无回调停止或内存持续增长；设备切换能停止旧数据并进入重新校准。

### M4：Windows 真实监控，只读

任务：

- 从现有 PyAudioWPatch 录音工具提取 loopback 流，不落盘；
- 匹配当前默认渲染端点和 loopback；
- 读取 EndpointVolume 与静音状态；
- 监听默认设备切换、端点断开和音量变化；
- 明确 shared-mode 与 exclusive-mode 的失败表现。

产物：Windows 只读适配器、设备能力报告、真实监控界面。

通过门禁：与 macOS 输出相同的状态契约；同名设备不会错误匹配；设备异常能明确降级。

### M5：响度指标校准

RMS/Peak 可先显示；只有此阶段完成后，界面和控制器才正式使用 `LUFS` 名称。

当前结果：实时算法与两平台只读适配器已经接入；六组合成信号离线误差在 0.001 LU 内。真实内容与 Windows 实机门禁尚未完成，详见 [`M5_CALIBRATION.md`](M5_CALIBRATION.md)。

任务：

- 实现或引入最小的 K-weighting 与 400 ms / 3 s 窗口；
- 用 Flowset/FFmpeg `ebur128` 作为离线参照，不放入实时主循环；
- 在 macOS、Windows 使用同一批合成信号和合法测试音频交叉验证；
- 测量 CPU、延迟、窗口启动和静音门行为。

产物：指标误差报告、性能报告、经验证的 meter 测试向量。

通过门禁：实时值在两个平台的允许误差内一致；未通过前只能显示 RMS/Peak，不能伪称 LUFS。

### M5.5：Peak Guard 爆音检测影子模式

这一阶段插在任何音量写入之前，只判断“是否发生突然爆音，以及理论上应衰减多少”。

当前结果：Python 与 macOS Swift 已实现一致的 10 ms 检测状态机，Windows WASAPI 与 macOS Core Audio 分别在本平台回调侧生成摘要；共享服务记录版本化影子事件，界面显示建议值和 `未执行`。合成测试已覆盖 30 ms 满幅突增、10 ms 单峰过滤、Hold/Release 回到待命。尚未进行真实通知音、强鼓点、切歌阶跃和 Windows 实机误触发验收。

任务：

- 增加 Sample Peak，并为后续 True Peak 预留独立字段；
- 计算 5–10 ms 快速能量和约 1 秒稳定基线；
- 用“绝对峰值 + 相对突增 + 最短持续时间”联合触发；
- 实现 `ARMED → ATTACK → HOLD → RELEASE` 状态机；
- 记录触发原因、建议衰减、Hold/Release 和 cooldown；
- UI 增加 Peak Guard 卡片与 `只记录` 状态，不增加执行按钮；
- 使用爆音脉冲、通知音、强鼓点、切歌阶跃和对白爆破音做误触发测试。

产物：跨平台共享检测器、合成爆音测试向量、影子事件日志和误触发报告。

通过门禁：同一 PCM 在 macOS/Windows 得到一致触发；能识别持续突增，强鼓点不会造成高频重复事件；全部动作保持建议状态，没有系统音量或 PCM 写入。

### M6：音量控制适配器，人工触发

当前结果：macOS 与 Windows 已实现独立人工写入适配器，共享 API 只接受 `lower` 和 `restore`。macOS 已在 `MacBook Pro扬声器` 实测从 18.75% 降到 17.75%，随后恢复到 18.75%；静音状态未改变。Windows 已通过模拟 EndpointVolume 测试，确认用户中途改音量后拒绝恢复，实机门禁仍未完成。

任务：

- macOS：探测并读写当前输出设备的可写音量属性；
- Windows：通过 EndpointVolume 设置主音量并标记本程序事件上下文；
- 识别用户操作与程序操作；
- 验证音量步进、静音、设备切换和退出行为；
- 完成每个设备的“小幅响应校准”。

此阶段只有界面上的人工测试按钮可以写音量，控制器仍不能自动执行。

退出策略：只有在当前值仍等于本程序最后写入值、期间没有用户接管时，才允许恢复基准音量；否则保持用户当前值。

产物：两平台音量适配器、设备校准记录、人工写入测试。

通过门禁：失败设备准确标记为只监控；任何错误都不会循环写音量或覆盖用户新设置。

### M7：影子模式

当前结果：macOS/Windows 真实入口均可选择 `monitor` 或 `shadow`；`lower-only` 与 `automatic` 仍被服务端拒绝。影子建议显示在界面并按平台写入 JSONL，不保存 PCM。自动测试确认持续偏响生成 `would-lower`、音量保持不变、静音阻止建议。真实音乐、通知音、对白和切歌的人工复核仍需积累，详见 [`M7_SHADOW_REPORT.md`](M7_SHADOW_REPORT.md)。

任务：

- 使用真实音频与真实系统音量运行控制器；
- 生成“建议调整”但不执行；
- 界面同时显示实际音量和建议音量；
- 收集不同内容和设备上的误触发、漏触发、建议频率。

产物：影子模式事件日志、可回放报告、参数调整记录。

通过门禁：人工复核通过安静段、切歌、通知音、对白、宽动态音乐和手动操作；没有持续升高建议。

### M8a：新策略影子闭环

2026-10-13 已确认 `MacBook Pro扬声器` 的 Core Audio tap 为 `pre-volume / high confidence`：同一首曲目前约 20 秒在 31%、50%、69% 系统音量下得到几乎重合的 Short-term 曲线，主要峰值均约为 −24 至 −25 LUFS。该结论只绑定当前设备与路由，不外推到其他 Mac 输出。

任务：

- 判定每个设备的捕获信号位于系统音量之前还是之后；
- Windows 读取端点 dB，macOS 建立设备独立的音量映射；
- 共享控制器改用 dB 比例、每秒限速、目标回差和窗口占比；
- 共用服务将 30 秒内相同的影子降低建议聚合成一个持续偏响事件；
- 继续只生成 `would-lower`，不执行音量写入；
- 真实音乐、对白、通知、切歌、暂停和淡出分别复核。

平台开发拆分：

| 阶段 | macOS | Windows | 共用层 |
|---|---|---|---|
| M8a-1 dB 能力 | 读取设备 dB、dB 范围及 scalar/dB 转换；不支持则标记不可映射 | 读取 EndpointVolume scalar、master dB、dB 范围和硬件支持 | 扩展观测契约与设备反馈档案 |
| M8a-2 捕获分类 | 当前内建扬声器写入 `pre-volume` 档案；其他设备逐个校准 | 每个 Endpoint ID 执行三档音量往返校准，不预设 loopback 位置 | 统一分类为 `pre-volume` / `post-volume` / `unreliable` |
| M8a-3 有效响度 | `sourceLufs + normalizedDeviceAttenuationDb` | pre-volume 时加端点衰减，post-volume 时直接使用捕获 LUFS | 控制器只使用可靠 `effectiveLufs`；否则仅作源响度 shadow |
| M8a-4 dB 建议 | 把目标 dB 转换为设备 scalar，只生成建议 | 直接生成端点目标 dB，只生成建议 | 比例下降、每秒限速、目标回差、窗口占比 |
| M8a-5 实机门禁 | 内建、蓝牙、USB/HDMI 分别留结果 | 扬声器、耳机、蓝牙与 exclusive-mode 失败路径分别留结果 | 同一 fixture 决策一致，UI 显示映射状态与置信度 |

M8a-1 已于 2026-10-13 完成代码与 macOS 只读验证：共享观测现在包含当前 dB、dB 范围、步长、相对设备最大值的衰减、映射来源与可靠性；控制器不再把原始设备 dB 直接当作输出衰减。本机 `BuiltInSpeakerDevice` 在 68.75% 时报告 −10.85 dB，范围 −63.5 至 0 dB，映射来源为 Core Audio 原生 dB 属性。Windows 已接入 `GetMasterVolumeLevel`、`GetVolumeRange` 与 `QueryHardwareSupport`，自动测试通过，待 Windows 实机复核。

M8a-2～M8a-4 已完成代码与自动测试：

- 按平台和设备 ID 保存反馈档案，系统环境、dB 来源或范围变化时自动失效；
- 引导校准每档使用最近稳定窗口的中位数，拒绝样本不足或音量移动中的数据；
- 三档数据统一分类为 `pre-volume`、`post-volume` 或 `unreliable`，档案不保存 PCM；
- `pre-volume` 使用 `sourceLufs + outputAttenuationDb`，`post-volume` 直接使用捕获 LUFS；
- 未校准、已失效或映射不可靠时不产生可执行的 dB 建议；
- 共享控制器按 `lowerGain`、`maxLowerDbPerSecond` 和 `minLowerStepDb` 生成限速建议；
- macOS 可把建议 dB 只读换算为 scalar，Windows 保留 EndpointVolume dB 执行边界给 M8b；
- 服务端继续拒绝真实自动模式，所有 M8a 动作都满足 `execute=false`。

M8a-5 当前状态：自动化代码门禁和 macOS 内建扬声器实机检查通过；Windows 实机与两平台外接设备矩阵待补齐。完整结果和待测项见 [`M8A_ACCEPTANCE_REPORT.md`](M8A_ACCEPTANCE_REPORT.md)。在这些物理门禁完成前，不开放 M8b。

设备反馈档案使用普通 JSON，至少记录平台、设备 ID、捕获位置、置信度、dB 来源与范围、映射是否可靠、校准时间和证据摘要。设备 ID、驱动/系统环境或 dB 范围变化时档案失效，自动退回 shadow。

M8a 的界面必须把“源 Short-term LUFS”与“有效输出响度”分开显示；后者不可计算时显示“未校准”，不能把当前蓝线冒充最终输出响度。

产物：设备反馈档案、新控制器、真实 shadow 日志、跨平台测试报告。

通过门禁：建议能够收敛到目标上沿；没有意外上调、阈值抖动或 Peak Guard 误写系统音量。

### M8b：只自动压低闭环

任务：

- 仅对已校准且可回读的设备开放 `lower-only`；
- 平台适配器把共享 dB 决定转换成系统实际音量；
- 每次写入前复核设备与用户接管状态，写入后回读验证；
- 设备变化、权限变化、写入不一致或捕获异常立即停止；
- 设置最低音量和每秒最大下降量硬限制。

产物：第一版可用下降闭环、动作日志、跨平台实机报告。

通过门禁：连续日常使用中没有意外上调、音量来回抖动或越界写入；用户手动操作立即生效。

### M9：可选的缓慢恢复

任务：

- 只在非静音、非暂停、非淡出且长时间低于目标时允许恢复；
- 不超过用户基准和设备最高限制；
- 恢复速度明显慢于压低速度；
- 作为独立开关，默认关闭直到试听通过。

产物：`automatic` 模式。

通过门禁：所有“音量爬升”测试通过，用户确认恢复节奏自然。

### M10：包装与日常运行

任务：

- 决定是否封装托盘应用；
- 加入单实例、正常退出、崩溃恢复和日志轮换；
- 分别生成 macOS 与 Windows 的可撤销安装/运行说明；
- 开机启动保持可选且默认关闭。

产物：可分发本地版本、安装/卸载说明、已知限制。

通过门禁：卸载后不遗留虚拟设备、系统扩展或自动启动项；MVP 本身不应安装这些内容。

## 6. 最终目标：DSP 爆音拦截分支

MVP 完成后开启独立技术分支。它不阻塞 M8，但属于最终产品完成条件：只有在第一个危险峰值到达真实设备前完成衰减，才算满足 REQ-17。

### D1：macOS 路由试验

- global tap 使用 `mutedWhenTapped` 或等价模式；
- 排除本程序输出，避免反馈；
- 接入 M5.5 Peak Guard、5 ms look-ahead、慢速 gain rider 和 peak limiter；
- 测量端到端延迟、漏音、时钟漂移、设备切换与崩溃恢复。
- 技术试验通过后，才评估 Audio Server Plug-in 虚拟输出设备；生产路径和进程边界见 [`MONITORING_AND_SUPPRESSION.md`](MONITORING_AND_SUPPRESSION.md#41-macos)。

### D2：Windows 方案选择

只做两条路线的技术评估：

- 自定义 APO；
- 自有虚拟输出设备。

比较驱动签名、安装权限、升级/卸载、端点兼容、低延迟和维护成本。WASAPI loopback 监听后直接重放不进入候选，因为无法阻止原声输出。

APO 路线必须把 Peak Guard 放在实时 `APOProcess`，共享服务只提供经过校验的配置快照和只读遥测；具体运行逻辑见 [`MONITORING_AND_SUPPRESSION.md`](MONITORING_AND_SUPPRESSION.md#42-windows)。

### D3：是否产品化的门禁

只有同时满足以下条件才进入正式开发：

- 两个平台都有可靠且可撤销的路由；
- 崩溃不导致持续静音；
- 不出现原声和处理声重叠；
- 延迟适合音乐和视频；
- 压缩/限幅能通过盲听，不明显破坏音乐动态；
- 用户明确接受额外权限和安装复杂度。

## 7. 测试矩阵

### 7.1 内容

- 静音和暂停；
- 低电平持续声音；
- 从低到高的音量阶跃；
- 从高到低的音量阶跃；
- 短通知音和单次峰值；
- 宽动态音乐；
- 持续高响度音乐；
- 对白、网页视频和多个来源切换；
- 淡入、淡出和曲间空白。

### 7.2 设备

| 平台 | 至少覆盖 |
|---|---|
| macOS | 内置扬声器、3.5 mm/USB、蓝牙、一个不可写音量的数字输出场景 |
| Windows | 内置/主板输出、USB、蓝牙、同名端点、默认设备切换、shared/exclusive 差异 |

### 7.3 故障

- 拒绝或撤销捕获权限；
- 输出设备断开；
- 默认设备切换；
- 音频回调停止或超时；
- 平台 helper 退出；
- 本机 API 或页面关闭；
- 设置文件损坏；
- 用户在自动调节期间按音量键；
- 应用异常退出后重新启动。

## 8. 每个阶段的统一完成条件

每个里程碑结束前必须同时满足：

1. 有一个最小、可重复的自动检查；
2. 异常路径不会写错音量或丢失用户设置；
3. 日志不包含原始音频和歌曲内容；
4. macOS/Windows 契约字段含义一致；
5. 新参数在界面、配置、控制器和日志中一致；
6. 文档记录已验证行为和未验证边界；
7. 未通过门禁不得提前开启下一等级的自动控制。

## 9. 第一轮实际工作包

开始编码时只做 M0–M2，不碰真实系统音量：

1. 写状态、设置和动作 JSON fixture；
2. 写控制器的六类合成时间序列测试；
3. 实现只监控/影子状态机；
4. 建立本机状态 API；
5. 将已确认的监控界面接入模拟数据；
6. 验证设置保存、刷新恢复和动作解释。

第一轮验收后，再分别开始 M3 macOS 和 M4 Windows 真实监控。这样可以在没有平台权限、驱动和设备差异干扰的情况下，先把产品行为定义正确。

## 10. MVP 完成定义

只有以下条件全部成立，才称为跨平台 MVP 完成：

- macOS 与 Windows 都能稳定读取当前输出设备的系统混音摘要；
- 监控界面显示真实系统音量、用户基准、自动修正、目标和动作原因；
- 设置经过服务端校验并能安全持久化；
- RMS/Peak 准确，显示为 LUFS 的指标已完成跨平台校准；
- 两个平台都通过设备切换、用户接管和故障降级测试；
- 影子模式报告经过人工复核；
- `lower-only` 模式通过日常使用，没有自动升高和明显抖动；
- 程序退出或崩溃不会持续占用音频设备或导致静音；
- 没有保存、上传或训练任何系统音频内容；
- 真正 DSP 压缩/限幅仍明确标记为后续独立能力。
