# 咖啡店情景建议标准流程

版本：1.0；建立日期：2026-10-19。

每次生成歌单前，返回可讨论、可照填前端、可追溯的情景策展报告，并留档。可由用户自行配置和生成；用户明确要求脚本生成并确认配置后，执行下方的脚本草稿分支。计算结果不代替实际试听验收。

## 1. 核对本次输入

记录目标日期、地点、播放区间、曲库绝对路径及SHA256、曲目数、模型版本、规则版本、扫描来源、标签来源和CD核实状态。

检查扫描与现行规则、源数据是否一致。需要重扫时复用现有扫描器并输出到新快照目录，不覆盖旧结果；输入未变时复用有效快照。核对当前曲库可用歌曲ID，库外曲目另列。

曲库初次使用或内容变更后使用 FlowSystem 现有曲库验证器；相同hash且已验证可引用前次结果及时间。曲库验证通过不等于全天排程可行。

## 2. 收集目标日期情景

| 信息 | 采集与判断要求 |
|---|---|
| 日历 | 核对月份、星期、具体日期、保留的节日和节气。农历、节气采用目标年份可靠历表；不凭记忆，不擅自设置节日预热，也不默认带年份日期每年复现。 |
| 天气 | 查询门店区域和目标日期，优先气象部门。能取得营业时间逐小时预报则使用；只有日预报就注明精度，不能推断具体钟点天气。 |
| 来源与时效 | 保存链接、来源发布/更新时间（未提供则写未知）、采集时间、有效日期/区间和地域。每轮重新核对天气；远期超出可靠预报范围就标待补，不借用邻日天气。 |
| 日出日落 | 按目标日期、坐标、时区计算或查询，记录方法和近似性；不固定深圳全年日落钟点。 |
| 营业时段 | 上午08–11、午间11–14、下午14–18，与实际播放区间求交；日出保留为开场意象，不要求真实日出在营业时段内。 |
| 傍晚天光 | 按当日天文时刻提出与营业区间相交的窗口，标为建议；可计算日落不能证明会有晚霞。 |
| 季节与体感 | 沿用已确认口径。当地季节和温度阈值未设定时不自动触发；秋季意象只能明确列为策展备选，不把月份等同深圳秋凉。 |

返回“适用情景、可选情景、未采用/缺失信息”的判断及原因。来源冲突时说明分歧与采用依据；无法消解就降低建议力度。无合适情景也可给普通听感编排，不制造命中。

## 3. 筛选歌曲并核对特征

从有效扫描与当前曲库交集筛选，以稳定歌曲ID关联，核对曲名、完整艺人及版本。情景证据、人工风格和个人听感分别保留。

- `pending`关联可以供讨论，不写成已正式批准或自动锁曲。保留 `explicit / indirect / ambiguous` 与理由；未命中不等于没有情景内容。
- 复合标题整体判断：“阴转晴”需要天气过程依据；“Sunday Am”不能只取早晨；“HOT”不能因高温自动认定为天气歌曲。
- 每首列主/副风格、器乐性与语言状态、噪音/摇摆/负担、能量及适用时段。缺项写缺失，不由标题、艺人或国籍猜测。
- 预测来自当前UI曲库并标模型版本，不混用另一份曲库。timeScores只是模型参考分数，不冒充人工时段标注或概率。
- “实际ZMPD”仅指人工标注。按同一音频SHA256确认绑定并回查原始反馈；不能用预测、均值或相似版本替代。
- 只有原标注录音、当前曲库缺hash时，单列“原录音人工参考／当前曲库绑定未核实”；核验原反馈及原音频，不写回当前真值，也不声称已验证同一录音的预测误差。
- 说明人工与预测明显不同对编排的影响，优先尊重已核实的人工判断；不因此修改生成器算法。未试听就依据标签和特征描述，不声称已听过。

提出少量核心与可替换候选，说明区段、理由、替换关系及试听需求。不固定每次三首，也不要求每种命中情景都安排。

## 4. 输出可照填的前端配置

核对当前页面说明/实现，配置以实际支持能力为准。现有参考页面支持分段、每段三节点曲线、宽容度、能量/风格偏好和“本段必选”。

每段给出：起止时间、分钟数、噪音/摇摆/负担各自的起点→中点→终点、宽容度、能量、完整风格名称、本段必选的准确歌曲/艺人及次数。

- 用段落承载时间要求，需更窄位置再拆段。不固定四段，不把本次天光窗口变成全年规则。
- 相邻三维曲线边界连续，总分钟数覆盖播放区间。默认宽容度±1，改动时说明；带内不扣曲线分，不等于带外绝对禁止。
- 能量和风格是偏好。当前必选按歌曲开始所在段计次，单曲次数1；不保证首曲或精确分钟。搜索后仍需点选准确条目并添加必选。
- 模型timeScores目前不自动约束生成器播放时段。
- 未跑排程则写明“未核验全天衔接、CD及覆盖可行性”；用户给生成结果后再单独核查，不能把数值检查当作生成成功。

不静默取消必选或放宽CD/衔接限制。用户未要求时，不操作浏览器、运行全天排程、确认导出、修改CD或导入QQ。另有浏览器授权时遵循当次偏好，本会话为Chrome，Firefox由用户使用。

## 5. 每次交付并归档

按 [报告模板](brief_template.md) 写报告。对话同时返回当日结论、情景表、重点候选特征表、前端配置和归档链接，不能只回复“已存档”。完整报告可额外保留较长的初筛池。

```text
  YYYY-MM-DD/
    r001/
      情景与手动配置建议.md
      evidence.json
    r002/
      情景与手动配置建议.md
      evidence.json
```

先查看该日期已有版本，取下一个未使用编号。首份r001；核实两个目标文件均不存在再写入，目录冲突则另取编号。修正已交付报告也新建版本，说明替代对象和原因，旧版保留并在索引标注“已被替代”。

每次更新 [归档索引](briefs/README.md)：目标日期、版本、采集时间、播放区间、方案状态、报告/证据链接及前版关系。版本属于策展报告，不是生成器确认版。

2026-10-20首份报告早于标准流程，保留日期根目录原路径，视为r001历史兼容记录；r002完成首次脚本试生成，r003完成每音乐段两类TAG的对照版，同日下一版从r004开始，原evidence不覆盖。

### 用户确认配置后的脚本草稿分支

用户可以选择不操作前端，由Agent调用现有脚本生成。先按FlowSystem仓库的 `.agents/skills/flowset-weekly/SKILL.md` 与 `docs/WEEKLY-WORKFLOW.md` 执行，复用 `tools/weekly_playlist.mjs`，不另写调度算法。

1. 确认目标日期、起止时间、各音乐段的TAG/能量、曲线/宽容度、情景歌曲与开始窗口、实际曲库和CD来源。用户明确“其他按建议”即可沿用，不重复询问已确认项。
2. 情景曲默认给不超过30分钟的开始窗口，用独立小段承载，继承所属音乐段的风格和能量。边界时间按当天情景设计；闭店延后不应自动拉长日落曲窗口。拆段后的曲线按原趋势重采样，记录变化并保持边界连续。
3. 同一版本目录保存 `request.json`，验证曲库后调用现有 `generate`，输出 `draft.json`。不运行确认导出或CD写入；失败时保留结果和原因，不静默放宽条件。
4. 独立核查连续覆盖、总分钟数、唯一歌曲ID、指定曲次数与实际开始窗口、衔接风险硬限制、预测来源及原CD文件不变。汇总风格/能量偏离、衔接偏好提示、末曲截短与未试听事项。
5. 返回完整曲目表与情景位置表，归档要求、草稿、报告、证据及便于阅读的完整歌单。报告区分“指定情景曲”和原算法普通选入的其他情景标题，不把普通入选冒充本次情景配置。

2026-10-20 r002运行时，标题扫描快照仍保留原08–18的门店过滤口径；本次按用户09:30–18:30覆盖生成，三个情景窗口均在旧保留范围内。后续涉及18点后的明确钟点标题时，需要核对并更新扫描，不能假定旧快照已覆盖新营业时间。

### evidence.json最低记录

新报告采用 `schemaVersion: context-playlist-brief/v1`。这是留档约定，不是已实现的自动校验或可导入前端的格式。

| 字段 | 内容 |
|---|---|
| runId / revision / supersedes | 唯一ID，如2026-10-20-r002；版本、前版ID和变更原因，无前版则null。 |
| targetDate / timezone / collectedAt / venue / playback | 明确日期、时区、采集时间、坐标、播放起止及默认值来源。 |
| status / execution | 默认proposed；分别记录建议、实际生成、确认和播放状态，提案不代表已生成。 |
| inputs | 实际使用的曲库、规则、扫描、标签、人工源路径、SHA256与版本；CD来源及核实状态。 |
| contexts / sources | 天气、日历、天文事实、来源、时间、有效范围及适用/可选/排除/未知判断。 |
| candidates | 稳定ID、准确标题/完整艺人/版本、库内状态、情景证据和复核状态、标签、预测模型、可绑定人工值或原录音参考、缺失及冲突。 |
| recommendations / segments | 核心、备选、不采用的理由，以及时段、分钟数、曲线、宽容度、能量/风格与必选次数。 |
| checks / limitations | 真正执行的检查及未核验事项，如CD、全天排程、试听和天气精度。 |
| outputs | 报告与证据路径，报告保留可理解的来源说明。 |

用户后续选择方案可另存有日期和授权依据的采用记录，或在下版说明；不回改原提案，不把选用某首曲当作永久批准关联，也不代替生成器CD账本。

## 交付前检查

确认日期与默认时段可见；资料对应目标日；没有恢复排除标签；核心与备选ID在当前库内；人工/预测区分且缺失可见；分钟数及共享边界正确；报告与证据一致；索引可打开；没有覆盖旧版或把建议冒充生成成功。
