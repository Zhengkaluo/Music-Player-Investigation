## 已确认的门店规则

门店：深圳景田咖啡店，东经 **114.04°**、北纬 **22.56°**，时区 `Asia/Shanghai`，营业区间 **08:00–18:00**（不含闭店端点）。

| 分组 | 保留内容 |
|---|---|
| 日历：季节 | 春、夏、秋、冬；低优先级，不由月份或天气反推 |
| 日历：月份 | 一月至十二月 |
| 日历：星期 | 星期一至星期日、周末；不把周末等同调休后的休息日 |
| 日历：日期 | 明确月日；保留原年份，不默认每年复现 |
| 日历：节日 | 元旦／新年、春节、元宵、端午、七夕、中秋、重阳、情人节、万圣节、圣诞节；历法需核实，按门店采用范围启用 |
| 日历：节气 | 二十四节气，完整保留；不表示当地实际天气 |
| 天气与体感 | 下雨、晴天／阳光、阴天、偏冷／凉爽、偏热 |
| 营业时段 | 上午 08:00–11:00、午间 11:00–14:00、下午 14:00–18:00 |
| 日出 | 保留为早晨开店意象，不要求实际日出与营业时间重叠 |
| 傍晚天光 | 傍晚、黄昏、暮色、日落、夕阳、晚霞统一归类；原标题词义仍保留，适用窗口须与营业时间重叠 |

咖啡／茶只保留为 `manual_themes` 手动主题，不参与自动标题扫描或日常加分。

四季整体、历法未确认月份、泛假日、泛祝贺、生日、雾、霜、风暴、雷电、温暖、傍晚风歇、泛太阳、月光、午夜、黄金时刻、山行、自然、植物、空间和活动扩展等退出日常关联；原有冰、露水、云、雪、风、夜晚、黎明等排除继续生效。退出的是关联，不是歌曲。

单纯的温度数值不直接产生偏冷／偏热标签，原文仍保存在标题审计中。早餐、午休为间接线索。明确钟点只有在营业区间内才保留，并归入对应营业时段。

## 合并与证据

- `tag_aliases` 统一旧标签；`association_groups` 定义合并后的名称与触发条件。82 条词表规则输出 68 种固定日常标签，另有按标题产生的具体日期。
- `source_associations` 保存合并前的标签、判断、理由、触发提示和原始证据；`evidence` 保留原文字符位置，不把晚霞改写成精确日落。
- `weather_changes` 保存雨后放晴、雨晴交替和阴转晴的组合信息；输出其天气分量，不再产生第三个独立变化标签。
- `scoring_groups` 标识共享依据：天气过程分量、具体日期与月份、星期与周末不得机械重复加分。该字段只记录约束，本目录没有排名加分引擎。
- `policy.excluded_tags` 在词表、解析器、语义附加项之后统一过滤，避免旧标签重扫回流。营业时间外钟点和其他被过滤项保存在 `title_audit.store_filtered`。

## 运行与验证

仅使用 Python 标准库。在项目根目录执行：

```sh
python3 -B SongBase/context_associations/scan_title_contexts.py --dry-run
python3 -B SongBase/context_associations/test_title_contexts.py
python3 -B SongBase/context_associations/scan_title_contexts.py --output-dir SongBase/context_associations/scans/2026-10-19
```

`--dry-run` 不写任何文件。同一输出目录会覆盖生成报告；保留新快照时指定不同目录。

## 实现边界

已实现门店标签归并、营业钟点过滤、证据保留、语义误命中修正和候选报告。季节口径、温度阈值、节日启用范围、傍晚窗口容差仍未设定。

日出开店意象与傍晚天光窗口要求已写入配置；扫描器尚未内置目标日期天文计算、天气接口、运行时匹配、正式确认库写回、排名加分或浏览器锁曲。Agent可按标准流程采集、计算并提出手动配置建议，不能据此宣称这些能力已接入生成器。标签规则确认不等于批准任意歌曲自动入选。

所有候选仍为 `review_status=pending`、`auto_lock_allowed=false`、触发提示 `enabled=false`。人工确认结果应独立保存，不直接编辑扫描产物。

历史需求讨论见 [情境关联功能需求与歌单生成影响](情境关联功能需求与歌单生成影响.md)，其中旧范围以本文件和现行规则为准。
